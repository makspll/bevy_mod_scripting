# Migrating from 0.23 to 0.24

## Scripts

### The `types` global is removed

It was deprecated in 0.23. Use `import_namespace`, or `world.get_type_by_name`:

```diff
- local Transform = types.Transform
+ local Transform = import_namespace("transform").Transform
+ -- or
+ local Transform = world.get_type_by_name("bevy_transform::components::transform::Transform")
```

### Types are no longer globals

Globals named after types, like `Vec3` or `Transform`, are gone: types sharing a short name used to shadow each other unpredictably. Import types from their namespace instead. Bevy types with bindings are grouped in namespaces by category (`math`, `ecs`, `time`, `transform`, `ui`, ...), BMS' types live in `bms`, see [Namespaces](../ScriptingReference/namespaces.md):

```diff
+ local Vec3 = import_namespace("math").Vec3
+ local Transform = import_namespace("transform").Transform
  local t = Transform.from_translation(Vec3.new(1, 2, 3))
```

There is no option to keep them.

### `world.get_type_by_name` takes a full path

Short names no longer resolve, neither for Rust types nor for script components. Pass the full type path, i.e. `world.get_type_by_name("bevy_transform::components::transform::Transform")` or `world.get_type_by_name("script.my_game.Enemy")`, or use `import_namespace`, which looks types up by short name within one namespace.

### Numbers can be on the left of operators

`2 * v` and `1 + v` now work like `v * 2` and `v + 1`. For the other arithmetic operators the value's type provides a reflected function, i.e. `1 - v` calls `rsub(v, 1)` and `1 / v` calls `rdiv(v, 1)`; vectors have both.

## Tooling

### Lua language server files

- Types are no longer declared as globals, they are fields of the tables `import_namespace` returns, so the language server now flags `Vec3` as an undefined global instead of accepting it.
- Generic types are declared once with their parameters, and used with their arguments, i.e. `Handle<Image>` for the handle `Image.load` returns. This needs version 3.17.0 or later of the language server. The functions and fields using handles used to be left out or typed as `any`.
- Generic types which the LAD file builder was not told about are still typed as `any`.
- The book lists types by namespace: the types page links to a page per namespace (what `import_namespace` takes, with `root` for types without a crate, such as primitives), which lists its types. The pages of the types themselves did not move. Functions on the variants of an enum are documented on the page of the enum as `Variant.function`, they used to be listed as global functions.
- `cargo xtask docgen` is removed, `cargo xtask docs` generates the same files in `assets/definitions`. It runs the docgen example with all the binding features, previously only the default ones were used, so the generated files left out the bindings which are not on by default, such as the asset functions. Pass `--test-bindings` to also document the functions available to the script tests, which `docgen` used to do.

## Rust

- Functions are no longer overloaded: registering a name which already exists on a namespace replaces the function, rather than adding an overload tried after it. Overloads were tried one by one, cloning the arguments and building an error for every miss, which made operators slower the more overloads a type had. Accept a `Union` or a `ScriptValue` for arguments of different types instead.
  - `ScriptFunctionRegistry::overwrite`, `overwrite_documented`, `iter_overloads` and `remove_all_overloads` are removed, use `register` and `remove`.
  - `WorldExtensions::try_call_overloads` is renamed to `call_operator`.
  - Language implementations should call the operator's `ScriptOperatorNames::reflected_script_function_name` on the right operand when only it is a value.
- `CoreGlobals::types`, `ScriptTypeCatalogue::flat_view` and `ScriptTypeCatalogue::duplicate_short_names` are removed.
- `ScriptComponentRegistry::find` and `WorldExtensions::get_type_by_name` only take a full path.
- The Lua language server backend no longer marks globals as deprecated: `TypeInstance` lost its `deprecated` field.
- LAD files describe generic types: `LadFile::generic_types` and `LadTypeDefinition::generic_type` are added (set the latter to `None` when building types by hand), and `LadFileBuilder::add_generic_type` declares a generic type by a pattern like `bevy_asset::handle::Handle<$A>`. Reflection only exposes the arguments of a generic type, so these are documented as opaque.
- `LuaType::Generic` holds the `args` of the instantiation instead of a `parent`, and the classes of the Lua declaration files are `local` tables instead of globals.
- mdbook documents a generic type on a page of its own rather than a page per instantiation.
- `CoreScriptGlobalsPlugin::register_static_references` is removed, types are no longer registered as globals. `CoreScriptGlobalsPlugin::filter` now only decides which types scripts can look up by name.
- Types with `script_bindings` from the bevy bindings crates, and all types of the bevy crates they cover, are put in category namespaces (see `set_crate_script_namespaces`). Use `app.override_script_namespace` to move a type elsewhere.

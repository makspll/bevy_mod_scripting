# 0.25.0 - Typed arguments

See the [migration guide](./0.24-to-0.25.md) for breaking changes.

## Typed arguments

Functions taking callbacks, names or tables of options are documented as exactly what they take, so the Lua language server checks the calls:

```rust,ignore
/// Spawns an enemy
#[derive(ScriptData)]
#[script_data(namespace = "game")]
struct SpawnOptions {
    name: String,
    speed: Option<Speed>,
    on_death: Option<FunctionOf<fn(V<Entity>) -> ()>>,
}

#[derive(ScriptData)]
#[script_data(namespace = "game")]
enum Speed {
    Named(ByName<Pace>),     // "Slow" | "Fast"
    Exact(f32),              // 2.5
}
```

```lua
game.spawn({ name = "goblin", speed = "Fast", on_death = function(entity) end }) -- `entity` is an ecs.Entity
game.spawn({ name = "goblin", speed = "fast" })   -- not a Pace
game.spawn({ speed = 2 })                         -- missing `name`
game.spawn({ name = "goblin", sped = 2 })         -- no field `sped`
```

- `FunctionOf<fn(A) -> R>`: a function, documented as `fun(arg1: A): R`, so the parameters of a callback written inline are typed.
- `ByName<E>`: a unit variant of a reflected enum, passed by its name as in Rust and documented as the names, `"Slow" | "Fast"`.
- `#[derive(ScriptData)]`: plain data, copied to and from scripts rather than referenced.
  - A struct is a map of its fields (a table in Lua, an object in Rune). Each field converts by its own type, so it can be a callback, a name or a union. Unknown, missing and mistyped fields are errors naming the field.
  - An enum whose variants each hold one value is the value of any of them, and may hold itself.
  - Both are data types in the book and the LAD file (`LadType::Data`): a class of the fields or an alias of the union in Lua.
- `ValueOf<A, R>` takes the conversion: `ValueOf<A, ScriptValue>` is any value, typed as whatever was passed, i.e. `fn boxed(v: ValueOf<A, ScriptValue>) -> V<MyBox<A>>` gives a `MyBox<integer>` for `boxed(5)`.

See [Typed arguments](../Summary/controlling-script-bindings.md#typed-arguments).

## Reactive UI (experimental)

`bevy_mod_scripting_reactive_ui` lets scripts describe `bevy_ui` trees with components and signals: a component runs once, and when state changes only the properties and regions which read it update. The API is the same in every language, and typed in the Lua declarations.

```lua
local Counter = ui.component("Counter", function(props)
    local count = ui.signal(props.start)
    return ui.node({ on_click = function() count:set(count:get() + 1) end }, {
        ui.text({ text = function() return "count: " .. count:get() end }),
    })
end)
ui.render("counter", Counter({ start = 0 }))
```

UIs are tested with `reactive_ui_test` (`ReactiveUiTestPlugin`, the `testing` feature): render, find elements by name or text, click them, and check their properties, layout, a text snapshot of the tree or what re-ran. Events run what they change before returning:

```lua
local s = t.render(Counter({ start = 1 }))
s:click(s:get_by_text("count: 1"))         -- reaches the handler of the node around the text
assert(s:query_by_text("count: 2") ~= nil)
```

See the [Reactive UI chapter](../ReactiveUi/introduction.md) and [testing UIs](../ReactiveUi/testing.md).

## Other changes

- Unions only try the types which could convert a value (`FromScript::could_convert`), instead of building an error for each type which can't.
- Nested unions are documented as one union, `Union<A, Union<B, C>>` is `A | B | C`.
- In the Lua language server files, function types in unions and lists are parenthesized: `fun(): a | b` returns the union.
- `WithDeps<F>` takes a function, or a list of a function and values it is called with first: `{ f, a, b }` calls `f(a, b, ..)`. It is how Rune, whose closures handed to BMS can't capture references, gives a callback its signals and entities.
- `Lazy<T>` takes a script value as it is, documented as a `T`, for functions which convert it later.
- `AppScriptCallbackRunners::run_in_context` runs Rust code calling stored script functions inside a script's context.
- A Lua function passed to Rust and back is the function itself, called without going through Rust. In Rune, `.call(..)` on a function which came from Rune calls it with Rune's own values.
- In the Lua declarations, the functions of generic types are fields of the generic class, `Signal<T>:get(): T`, and generic functions have no untyped overload any more, which widened what typed calls return.
- In the book, long unions in tables of fields are folded, and optional fields are marked.
